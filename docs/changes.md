# Change register

Rule: **one change = one version = one run.** Every option in a command is added only after an observed error justifies it:
run, count the errors, fix the most frequent one, run again. `PERFORMANCE_LOG.md` (generated by `python analyze.py`) has the
numbers; the "Run log" below records, for each run, the command, what changed against the previous run
and which errors we saw.

## Condition, run, seed (since 25 Nov 2026)

A row of the run log is a **condition**: one step with one change (B4_strong, R2_2b). Since 25 Nov 2026 every condition
can have several **runs**: `experiments/<condition>/<person>_<n>/` (e.g. `B4_strong/vanessa_1`, `B4_strong/jan_1`), each
with the same 5 seeds. The person comes from the machine (`config.RUNNERS`). A repetition is started with `--repeat`; a
reflection run names the base run it reflects on (`--base B4_strong/jan_1`).

Results are averaged in two stages (`PERFORMANCE_LOG.md`, section 0): first over the 5 seeds of a run, then over the
runs. A reflection condition is compared with its base run by run (paired), because each run reflects on its own
frozen v1s. All runs B1-R3 below were run by Vanessa and are `<condition>/vanessa_1`.

## Two series

Prefixes: **E** = experiment of the old series, **S** = smoke test, **B** = baseline step (Step 1), **R** = reflection step (Step 2). The letters follow the steps of the course; later steps are **T** tools, **P** planning, **M** multi-agent. A change to the scoring is not a step and not a run, so its row in the run log has no letter ("– (no run)").

- **Old series E01-E21** (until 8 Nov 2026, frozen). Measured with the old prompts (v1-v4; "strong" undefined up to v3).
  It stays as history in `experiments/_legacy/`; nothing in it was deleted or renamed. E14-E21 are Jan's reruns of
  baseline v3 and the new baseline v4, each with 2a-2c (moved to `_legacy` on 25 Nov 2026).
- **New series S0, B1-B3, ... (from 9 Nov 2026).** A fresh start from the smoke test. One run (5 seeds) per step. Not comparable
  one-to-one with the old series, because the starting point differs.

Noise: five seeds per run already show how much a result varies inside a run. Large jumps (an error that hits 4 of 5 seeds
and then 0 of 5) are bigger than that noise. Separate repeat runs are planned only when differences become small (fine-tuning
after the reflection steps).

### Commands (machine with Docker and Ollama running; start the next run only when the previous one is finished)

```
python step1_baseline.py --exp B1_original_prompt --prompt step1_baseline_v1 --seeds 101-105 --change "Start of new series: original prompt (E01), no schema, no shims"
python step1_baseline.py --exp B2_schema --prompt step1_baseline_v1 --schema --seeds 101-105 --change "B1 + schema in the prompt"
python step1_baseline.py --exp B3_shims --prompt step1_baseline_v1 --schema --shims --seeds 101-105 --change "B2 + shims"
python step1_baseline.py --exp B4_strong --prompt step1_baseline_v2 --schema --shims --seeds 101-105 --change "B3 + prompt defines strong"
python step2_reflection.py --exp R1_2a --level 2a --base B4_strong --change "B4 + reflection 2a (own code only)"
python step2_reflection.py --exp R2_2b --level 2b --base B4_strong --change "B4 + reflection 2b (sees run output)"
python step2_reflection.py --exp R3_2c --level 2c --base B4_strong --change "B4 + reflection 2c (sees run output and fact check)"
python analyze.py        # rebuilds PERFORMANCE_LOG.md
```

Since 25 Nov 2026 these runs live in `experiments/<condition>/vanessa_1/`. A repetition of a condition: the same command
with `--repeat` instead of `--change` (e.g. `B4_strong/jan_1`); for R1-R3 add the base run, e.g.
`--base B4_strong/jan_1 --repeat`.

After each run: `python analyze.py`, then read the error categories of the run in `PERFORMANCE_LOG.md` and
`python analyze.py --trace <condition>/<run> 101` for one trace. Write the top errors into the table above before the next run.

## Entry template for a new run or change

```
| Bn | date | what exactly differs from the previous run (one thing) | top errors we saw | decision |
```

A repetition of a condition is not a new row: add its run (e.g. `jan_1`) to the existing row and compare the numbers in
`PERFORMANCE_LOG.md` section 0.

After the baseline is settled, run the reflection levels on the best baseline (`step2_reflection.py --base <baseline run>`);
the old reflection results (E03-E21) do not carry over.
